# egp-watch — เฝ้าดูงานใหม่จาก e-GP

บอกว่ามีงานใหม่ในกลุ่มที่สนใจเข้ามาไหม แล้วเติมเข้าไฟล์ข้อมูลกับรายงานให้เอง

## ทำไมต้องมี 2 ชั้น

| ช่องทาง | อัตโนมัติ | เห็นดีลที่ยังยื่นได้ |
|---|---|---|
| API สพร. (`egp-contract`) | ✅ | ❌ **มีแต่โครงการที่ทำสัญญาแล้ว** |
| หน้าเว็บ e-GP | ❌ มี Cloudflare Turnstile | ✅ ครบทุกสถานะ |

ทดสอบแล้ว: โครงการ "ยังยื่นได้" 16 รายการในไฟล์ **ไม่มีใน API เลยสักรายการ**
และ API ครอบคลุมแค่ 37–62% ของสิ่งที่หน้าเว็บมี → **ชั้นที่ 2 จึงตัดไม่ได้**

> **ข้อค้นพบ 18 ก.ย. 2569 — API อัปเดตเป็นรอบเดือน**
> ชุดข้อมูล `egp-contract` มีรายการล่าสุดถึง **31 ส.ค. 69** เท่านั้น (ตรวจ 3 คีย์เวิร์ดตรงกันหมด)
> แปลว่าระหว่างเดือน ชั้นที่ 1 จะไม่เจออะไรใหม่เลย ไม่ใช่เพราะไม่มีงาน แต่เพราะต้นทางยังไม่ปล่อยข้อมูล
> **ระหว่างเดือนต้องใช้ชั้นที่ 2 เท่านั้น** — รอบ 18 ก.ย. ชั้นที่ 2 เจอดีลที่ยังยื่นได้ที่ API ไม่มี 5 รายการ
> รวม 44.5 ล. (ระบบสารสนเทศ รพ.ธรรมศาสตร์) และ 13.8 ล. (ตู้จ่ายยา ER รพ.ราชวิถี)

## ติดตั้งครั้งเดียว

สร้างไฟล์ `egp-watch/.env` (ถูก gitignore ไว้แล้ว):

```
EGP_API_KEY=<token ของคุณ>
```

ขอ token ฟรีที่ https://opend.data.go.th/register_api → ต้องเป็นสิทธิ์บริการ **govspending**

## ชั้นที่ 1 — ดึงข้อมูลใหม่ (สั่งเมื่อต้องการ)

### วิธีที่ 1 — กดปุ่มในรายงาน (สะดวกสุด)

```bash
node egp-watch/serve.js
```

เปิด http://127.0.0.1:8899/medication-market-report.html แล้วกดปุ่ม
**"ดึงข้อมูลใหม่ตอนนี้"** มุมขวาบน — ใช้เวลาราว **3–4 นาที** เสร็จแล้วกด "โหลดรายงานใหม่"

> เปิดไฟล์ `.html` ตรง ๆ (file://) ปุ่มจะสั่งงานไม่ได้ เพราะหน้าเว็บรันคำสั่งเองไม่ได้
> กรณีนั้นปุ่มจะคัดลอกคำสั่งให้เอาไปวางในเทอร์มินัลแทน

### วิธีที่ 2 — สั่งจากเทอร์มินัล

```bash
node egp-watch/watch-daily.js --dry-run   # ดูเฉย ๆ ไม่แก้ไฟล์
node egp-watch/watch-daily.js             # ทำจริง
```

แต่ละรอบ: ยิงคีย์เวิร์ดตาม `config.js` → คัดกรอง → เทียบของเดิม →
เขียน `digest/งานใหม่-YYYY-MM-DD.md` → เติมแถวเข้าไฟล์ `.md` → สร้างรายงาน HTML ใหม่

### ถ้าอยากให้รันเองทุกวัน

ตอนนี้**ไม่ได้ตั้งไว้** (ตามที่สั่ง) ถ้าเปลี่ยนใจ ให้รันคำสั่งนี้ใน Command Prompt:

    schtasks /Create /TN "egp-watch" /SC DAILY /ST 08:30 /TR "node C:\Users\Lenovo\Documents\App_dev\CRM_app\egp-watch\watch-daily.js"

ยกเลิก: `schtasks /Delete /TN "egp-watch" /F`

## ชั้นที่ 2 — เช็คหน้าเว็บด้วยตัวเอง (~5 นาที)

ทำเมื่ออยากรู้ว่ามีดีลที่**ยังยื่นได้**เข้ามาใหม่ไหม (API บอกไม่ได้)

1. เปิด https://process5.gprocurement.go.th/egp-agpc01-web/announcement
2. ค้นทีละคำตาม `MANUAL_KEYWORDS` ใน `config.js` เลือกปีงบปัจจุบัน
   — **ดูเฉพาะสถานะ "ประกาศเชิญชวน" กับ "จัดทำ/วิจารณ์ร่าง TOR"**
3. คลุมตารางผลลัพธ์ → Ctrl+C → วางในไฟล์ `egp-watch/inbox/YYYY-MM-DD-<กลุ่ม>.txt`
4. `node egp-watch/import-manual.js --group=his egp-watch/inbox/2026-09-18-his.txt`

> **ต้องใส่ `--group=med` หรือ `--group=his` เสมอ** — ถ้าไม่ใส่ สคริปต์จะเดาโดยเลือก
> *กลุ่มแรกที่มีรายการใหม่* ซึ่ง `GROUPS` เรียง `med` ไว้ก่อน → งานของ HIS จะถูกเทลงไฟล์ระบบยาแทน
> และ **หนึ่งไฟล์ = หนึ่งกลุ่ม** ถ้าได้ทั้งสองกลุ่มให้แยกเป็นสองไฟล์แล้วรันสองรอบ

สถานะที่ "ยังยื่นได้" จะถูกติดธง 🔥 ให้อัตโนมัติ (`ประกาศเชิญชวน` → `🔥 ประกาศเชิญชวน`)
ถ้าไม่มีธงนี้ `pipeline/extract-*.js` จะไม่นับเป็น `isOpen` แล้วดีลจะไม่ขึ้นในรายงานเลย

## รีวิวรายการที่เพิ่งนำเข้า

หลังดึงข้อมูล เปิดแทป **“รายการใหม่”** ในรายงาน — จะแยกตามรอบการดึง (นำเข้าเมื่อ วันเวลา)
พร้อมชื่อโครงการ หน่วยงาน วงเงิน สถานะ ผู้ชนะ และ**คีย์เวิร์ดที่ทำให้ติดเข้ามา**

ตัวกรองอัตโนมัติดักคำพ้องภาษาไทยไว้แล้ว แต่หลุดได้ ถ้าเจอรายการที่ไม่ควรอยู่:

1. ติ๊กเลือกรายการนั้น → กด **“คัดลอกเลขที่เลือก”** (ได้คำสั่งพร้อมวางมาเลย)
2. วางในเทอร์มินัล:

       node egp-watch/remove-ids.js 69012345678 69087654321

สคริปต์จะลบแถวออก · เรียงเลขลำดับใหม่ · อัปเดตยอดหัว section · สร้างรายงานใหม่
และ**จำไว้ว่าไม่เอา** (`state/removed-ids.json`) รอบดึงถัดไปจะไม่ดึงกลับมาอีก

ดูผลก่อนได้ด้วย `--dry-run`:

```bash
node egp-watch/remove-ids.js --dry-run 69012345678
```

> **ลบได้เฉพาะรายการที่นำเข้าเพิ่มเท่านั้น** — ชุดข้อมูลจากหน้าเว็บที่ตรวจสอบยอดแล้ว
> (ระบบยา 444 · HIS 1,447) สคริปต์จะปฏิเสธ ไม่ยอมแตะ

## สิ่งที่เห็นในรายงาน

- **แถบบนสุด** — วันเวลาที่ข้อมูลใหม่เข้ามาล่าสุด · จำนวนที่เพิ่ม · จำนวนงานที่ยังยื่นได้
- **ปุ่ม "ดูเฉพาะงานที่ยังยื่นได้"** — กรองเฉพาะ *ประกาศเชิญชวน* และ *จัดทำ/วิจารณ์ร่าง TOR*
- **คอลัมน์ "เพิ่มเมื่อ"** — คลิกหัวคอลัมน์เรียงได้ ดูว่างานไหนเข้ามาก่อนหลัง
- **ป้ายในแถว** — `ใหม่ MM/DD` (เขียว) และ `ยังยื่นได้` (ส้ม)

## โครงสร้าง

```
config.js            ← แก้คีย์เวิร์ด/กลุ่มที่สนใจที่นี่ที่เดียว
lib/api.js           เรียก API (ส่ง api-key ทั้ง header และ query — ส่งอย่างเดียวไม่พอ)
lib/filter.js        เกณฑ์คัดเข้า/ออก
lib/mdtable.js       อ่าน/เขียนแถวตารางในไฟล์ .md
lib/addedlog.js      บันทึกว่าแต่ละโครงการเข้ามาเมื่อไร
watch-daily.js       ชั้นที่ 1
remove-ids.js        ลบรายการที่รีวิวแล้วพบว่าไม่ควรอยู่
import-manual.js     ชั้นที่ 2
serve.js             เปิดรายงาน + รับคำสั่งจากปุ่ม (127.0.0.1:8899)
build-reports.js     สร้างรายงาน HTML ใหม่จากไฟล์ .md
pipeline/            extract .md → JSON
templates/           ต้นแบบรายงาน HTML  ← แก้หน้าตารายงานที่นี่ แล้ว build ใหม่
state/               known-ids.json · added-log.json · removed-ids.json · data-*.json  (gitignore)
digest/              ผลแต่ละรอบ
inbox/               ที่วางผลจากหน้าเว็บ                              (gitignore)
```

**สำคัญ:** แก้หน้าตารายงานต้องแก้ที่ `templates/` แล้วรัน `node egp-watch/build-reports.js`
ถ้าไปแก้ `.html` ที่ root โดยตรง จะถูกเขียนทับรอบถัดไป

ผลดิบจาก API ปนของนอกขอบเขตมาก — รอบทดสอบ 3,742 รายการเหลือของจริง 486

| คีย์เวิร์ด | ไปแมตช์ผิดกับ |

| `HIS` | **BETA*HIS*TINE** (ชื่อยา) |

และงานก่อสร้าง/โครงสร้างพื้นฐาน (cloud · เครื่องแม่ข่าย · WiFi) ตามเกณฑ์ที่ไฟล์ `.md` ประกาศไว้เอง

**ถ้าเห็นของหลุดเข้ามาผิด** → แก้ `lib/filter.js` แล้วรัน `--dry-run` ดูผลก่อน

### กลุ่มที่ 3 — คลัง/เวชภัณฑ์ · ERP (เพิ่ม 18 ก.ย. 2569)

ไฟล์ `egp-inventory-erp-2569.md` → `inventory-market-report.html` · 78 โครงการ · 62.1 ล้านบาท

**ตลาดถูกครองโดยผลิตภัณฑ์เดียว** — `HERP Copilot` 51/78 โครงการ (65%) ใน 50 หน่วยงาน
ซื้อครั้งแรก 374k–497k แล้วต่อ Activation รายปีละ 32,100 บาท · ผู้ขายอันดับ 1 คือ
`บริษัท เอช อี อาร์ พี จำกัด` 30 งาน 14 จังหวัด

**กับดักที่ดักไว้แล้ว ห้ามแก้กลับ**
- `ERP` ต้องใช้ขอบเขตคำ `\b(?:H)?ERP\b` ไม่งั้นไปโดน **CAT·ERP·ILLAR** (เครื่องกำเนิดไฟฟ้า)
  และ **FISH·ERP·AYKEL** (เครื่องช่วยหายใจ) — แต่ต้องคง `H?` ไว้เพื่อเก็บ `HERP Copilot`
- `…คลัง` ต้องต่อท้ายด้วย `(?!ข้อมูล|ข้อสอบ)` — `โปรแกรมคลังข้อมูลด้านการแพทย์` คือ data warehouse
- `EPR` **ห้ามใช้เป็นคีย์เวิร์ด** — 521 รายการเป็นโหมด Expiratory Pressure Relief ของเครื่อง CPAP
  กับยี่ห้อแล็บ EPREDIA ไม่ใช่ซอฟต์แวร์ (ดูตารางคำที่ไม่ใช้ในภาคผนวกของไฟล์ .md)
- กลุ่มนี้ตั้ง `excludeIdsFrom: ['med','his']` ไว้ใน `config.js` เพราะไฟล์ประกาศว่าไม่ซ้ำกับสองไฟล์เดิม
  (ตั้งเป็นรายกลุ่ม ไม่ใช่กฎรวม — `med` กับ `his` จงใจใช้เลขซ้ำกัน 243 รายการจาก section eMAR)
