# egp-watch — เฝ้าดูงานใหม่จาก e-GP

บอกว่ามีงานใหม่ในกลุ่มที่สนใจเข้ามาไหม แล้วเติมเข้าไฟล์ข้อมูลกับรายงานให้เอง

## ทำไมต้องมี 2 ชั้น

| ช่องทาง | อัตโนมัติ | เห็นดีลที่ยังยื่นได้ |
|---|---|---|
| API สพร. (`egp-contract`) | ✅ | ❌ **มีแต่โครงการที่ทำสัญญาแล้ว** |
| หน้าเว็บ e-GP | ❌ มี Cloudflare Turnstile | ✅ ครบทุกสถานะ |

ทดสอบแล้ว: โครงการ "ยังยื่นได้" 16 รายการในไฟล์ **ไม่มีใน API เลยสักรายการ**
และ API ครอบคลุมแค่ 37–62% ของสิ่งที่หน้าเว็บมี → **ชั้นที่ 2 จึงตัดไม่ได้**

> **ข้อค้นพบ 18 ก.ย. 2569 — API อัปเดตเป็นรอบเดือน**
> ชุดข้อมูล `egp-contract` มีรายการล่าสุดถึง **31 ส.ค. 69** เท่านั้น (ตรวจ 3 คีย์เวิร์ดตรงกันหมด)
> แปลว่าระหว่างเดือน ชั้นที่ 1 จะไม่เจออะไรใหม่เลย ไม่ใช่เพราะไม่มีงาน แต่เพราะต้นทางยังไม่ปล่อยข้อมูล
> **ระหว่างเดือนต้องใช้ชั้นที่ 2 เท่านั้น** — รอบ 18 ก.ย. ชั้นที่ 2 เจอดีลที่ยังยื่นได้ที่ API ไม่มี 5 รายการ
> รวม 44.5 ล. (ระบบสารสนเทศ รพ.ธรรมศาสตร์) และ 13.8 ล. (ตู้จ่ายยา ER รพ.ราชวิถี)

## หน้ารวมรายงาน — `market-reports.html` (เพิ่ม 30 ก.ย. 2569)

```bash
node egp-watch/serve.js     # แล้วเปิด http://127.0.0.1:8899/
```

รวมทุกอย่างไว้หน้าเดียว มี 4 แทป: **ภาพรวม** (การ์ดสรุปแต่ละรายงาน + ปุ่มเปิดรายงาน) ·
**รายการใหม่** (ทุกรอบการดึง กรองตามกลุ่ม/ค้นได้) · **ยังยื่นได้** (รวมทุกกลุ่ม) · **ไฟล์ทั้งหมด**
(รายงาน HTML · ไฟล์ .md · digest · คู่มือ) — ทุกแถวมีปุ่ม **"เปิดใน e-GP"** ไปหน้าโครงการจริง

ปุ่ม **"ดึงข้อมูลใหม่ตอนนี้"** สั่งผ่าน `/start` แล้วถาม `/status` ทุก 3 วินาที (แสดง log สด)
เพราะรอบเต็ม 4 กลุ่มใช้เวลาเกิน 10 นาที · หน้านี้สร้างโดย `build-reports.js` จาก `templates/portal.html`

**ลิงก์ e-GP จากเลขโครงการ** — แถวที่มาจาก API ไม่มีลิงก์มาด้วย `lib/egplink.js` สร้างให้ตอน build
(token = AES ของ `{"projectId":"…"}` ด้วย passphrase `RDCrypto` ตามโค้ดหน้าเว็บ e-GP — ตรวจแล้วว่า
ถอด token เดิมได้ตรงเลขโครงการ และลิงก์ที่สร้างเปิดหน้าโครงการได้จริง) ถ้าวันหนึ่ง e-GP เปลี่ยน
passphrase ลิงก์ที่สร้างจะเปิดไม่ขึ้น ให้หาค่าใหม่จาก `encryptData()` ในบันเดิล `egp-agpc01-web`

### แชร์รายงานให้คนอื่น (ZIP ส่ง LINE / อีเมล)

```bash
node egp-watch/make-share.js    # → share/egp-market-reports-YYYY-MM-DD.zip (~1 MB)
```

รายงานทุกไฟล์ฝังข้อมูลไว้ในตัวแล้ว สคริปต์แค่คัดลอกหน้ารวมกับรายงานทั้ง 4 ไฟล์ไปไว้ในโฟลเดอร์เดียว
แล้วซ่อนส่วนที่ใช้ได้แค่บนเครื่องเรา (ปุ่ม "ดึงข้อมูลใหม่ตอนนี้", ลิงก์ .md และแท็บไฟล์ทั้งหมด)
ไฟล์ต้นฉบับไม่ถูกแก้ · ผู้รับต้องแตกไฟล์ ZIP ก่อน แล้วเปิด `market-reports.html` · โฟลเดอร์ `share/` ถูก gitignore
ถ้าจะส่งแค่ไฟล์เดียว (เช่น `medication-market-report.html`) ก็เปิดได้เหมือนกัน เพียงแต่ลิงก์กลับไปหน้ารวมจะใช้ไม่ได้

## ชั้นที่ 1 — ดึงข้อมูลใหม่ (สั่งเมื่อต้องการ)

### วิธีที่ 1 — กดปุ่มในรายงาน (สะดวกสุด)

```bash
node egp-watch/serve.js
```

เปิด http://127.0.0.1:8899/medication-market-report.html แล้วกดปุ่ม
**"ดึงข้อมูลใหม่ตอนนี้"** มุมขวาบน — ใช้เวลาราว **3–4 นาที** เสร็จแล้วกด "โหลดรายงานใหม่"

> เปิดไฟล์ `.html` ตรง ๆ (file://) ปุ่มจะสั่งงานไม่ได้ เพราะหน้าเว็บรันคำสั่งเองไม่ได้
> กรณีนั้นปุ่มจะคัดลอกคำสั่งให้เอาไปวางในเทอร์มินัลแทน

### วิธีที่ 2 — สั่งจากเทอร์มินัล

```bash
node egp-watch/watch-daily.js --dry-run   # ดูเฉย ๆ ไม่แก้ไฟล์
node egp-watch/watch-daily.js             # ทำจริง
```

แต่ละรอบ: ยิงคีย์เวิร์ดตาม `config.js` → คัดกรอง → เทียบของเดิม →
เขียน `digest/งานใหม่-YYYY-MM-DD.md` → เติมแถวเข้าไฟล์ `.md` → สร้างรายงาน HTML ใหม่

### ถ้าอยากให้รันเองทุกวัน

ตอนนี้**ไม่ได้ตั้งไว้** (ตามที่สั่ง) ถ้าเปลี่ยนใจ ให้รันคำสั่งนี้ใน Command Prompt:

    schtasks /Create /TN "egp-watch" /SC DAILY /ST 08:30 /TR "node C:\Users\Lenovo\Documents\App_dev\CRM_app\egp-watch\watch-daily.js"

ยกเลิก: `schtasks /Delete /TN "egp-watch" /F`

## ชั้นที่ 2 — เช็คหน้าเว็บด้วยตัวเอง (~5 นาที)

ทำเมื่ออยากรู้ว่ามีดีลที่**ยังยื่นได้**เข้ามาใหม่ไหม (API บอกไม่ได้)

1. เปิด https://process5.gprocurement.go.th/egp-agpc01-web/announcement
2. ค้นทีละคำตาม `MANUAL_KEYWORDS` ใน `config.js` เลือกปีงบปัจจุบัน
   — **ดูเฉพาะสถานะ "ประกาศเชิญชวน" กับ "จัดทำ/วิจารณ์ร่าง TOR"**
3. คลุมตารางผลลัพธ์ → Ctrl+C → วางในไฟล์ `egp-watch/inbox/YYYY-MM-DD-<กลุ่ม>.txt`
4. `node egp-watch/import-manual.js --group=his egp-watch/inbox/2026-09-18-his.txt`

> **ต้องใส่ `--group=` เสมอ** (`med` · `his` · `inv` · `log`) — ถ้าไม่ใส่ สคริปต์จะเดาโดยเลือก
> *กลุ่มแรกที่มีรายการใหม่* ซึ่ง `GROUPS` เรียง `med` ไว้ก่อน → งานของ HIS จะถูกเทลงไฟล์ระบบยาแทน
> และ **หนึ่งไฟล์ = หนึ่งกลุ่ม** ถ้าได้หลายกลุ่มให้แยกไฟล์แล้วรันทีละรอบ

สถานะที่ "ยังยื่นได้" จะถูกติดธง 🔥 ให้อัตโนมัติ (`ประกาศเชิญชวน` → `🔥 ประกาศเชิญชวน`)
ถ้าไม่มีธงนี้ `pipeline/extract-*.js` จะไม่นับเป็น `isOpen` แล้วดีลจะไม่ขึ้นในรายงานเลย

## รีวิวรายการที่เพิ่งนำเข้า

หลังดึงข้อมูล เปิดแทป **“รายการใหม่”** ในรายงาน — จะแยกตามรอบการดึง (นำเข้าเมื่อ วันเวลา)
พร้อมชื่อโครงการ หน่วยงาน วงเงิน สถานะ ผู้ชนะ และ**คีย์เวิร์ดที่ทำให้ติดเข้ามา**

ตัวกรองอัตโนมัติดักคำพ้องภาษาไทยไว้แล้ว แต่หลุดได้ ถ้าเจอรายการที่ไม่ควรอยู่:

1. ติ๊กเลือกรายการนั้น → กด **“คัดลอกเลขที่เลือก”** (ได้คำสั่งพร้อมวางมาเลย)
2. วางในเทอร์มินัล:

       node egp-watch/remove-ids.js 69012345678 69087654321

สคริปต์จะลบแถวออก · เรียงเลขลำดับใหม่ · อัปเดตยอดหัว section · สร้างรายงานใหม่
และ**จำไว้ว่าไม่เอา** (`state/removed-ids.json`) รอบดึงถัดไปจะไม่ดึงกลับมาอีก

ดูผลก่อนได้ด้วย `--dry-run`:

```bash
node egp-watch/remove-ids.js --dry-run 69012345678
```

> **ลบได้เฉพาะรายการที่นำเข้าเพิ่มเท่านั้น** — ชุดข้อมูลจากหน้าเว็บที่ตรวจสอบยอดแล้ว
> (ระบบยา 444 · HIS 1,447) สคริปต์จะปฏิเสธ ไม่ยอมแตะ

## สิ่งที่เห็นในรายงาน

- **แถบบนสุด** — วันเวลาที่ข้อมูลใหม่เข้ามาล่าสุด · จำนวนที่เพิ่ม · จำนวนงานที่ยังยื่นได้
- **ปุ่ม "ดูเฉพาะงานที่ยังยื่นได้"** — กรองเฉพาะ *ประกาศเชิญชวน* และ *จัดทำ/วิจารณ์ร่าง TOR*
- **คอลัมน์ "เพิ่มเมื่อ"** — คลิกหัวคอลัมน์เรียงได้ ดูว่างานไหนเข้ามาก่อนหลัง
- **ป้ายในแถว** — `ใหม่ MM/DD` (เขียว) และ `ยังยื่นได้` (ส้ม)

## โครงสร้าง

```
config.js            ← แก้คีย์เวิร์ด/กลุ่มที่สนใจที่นี่ที่เดียว
lib/api.js           เรียก API (ส่ง api-key ทั้ง header และ query — ส่งอย่างเดียวไม่พอ)
lib/filter.js        เกณฑ์คัดเข้า/ออก
lib/mdtable.js       อ่าน/เขียนแถวตารางในไฟล์ .md
lib/addedlog.js      บันทึกว่าแต่ละโครงการเข้ามาเมื่อไร
lib/egplink.js       สร้างลิงก์หน้าโครงการ e-GP จากเลขโครงการ
watch-daily.js       ชั้นที่ 1
remove-ids.js        ลบรายการที่รีวิวแล้วพบว่าไม่ควรอยู่
import-manual.js     ชั้นที่ 2
serve.js             เปิดรายงาน + รับคำสั่งจากปุ่ม (127.0.0.1:8899)
build-reports.js     สร้างรายงาน HTML ใหม่จากไฟล์ .md + หน้ารวม market-reports.html
pipeline/            extract .md → JSON
templates/           ต้นแบบรายงาน HTML  ← แก้หน้าตารายงานที่นี่ แล้ว build ใหม่
state/               known-ids.json · added-log.json · removed-ids.json · data-*.json  (gitignore)
digest/              ผลแต่ละรอบ
inbox/               ที่วางผลจากหน้าเว็บ                              (gitignore)
```

**สำคัญ:** แก้หน้าตารายงานต้องแก้ที่ `templates/` แล้วรัน `node egp-watch/build-reports.js`
ถ้าไปแก้ `.html` ที่ root โดยตรง จะถูกเขียนทับรอบถัดไป

ไฟล์ `egp-inventory-erp-2569.md` → `inventory-market-report.html` · 78 โครงการ · 62.1 ล้านบาท

**ตลาดถูกครองโดยผลิตภัณฑ์เดียว** — `HERP Copilot` 51/78 โครงการ (65%) ใน 50 หน่วยงาน
ซื้อครั้งแรก 374k–497k แล้วต่อ Activation รายปีละ 32,100 บาท · ผู้ขายอันดับ 1 คือ

**กับดักที่ดักไว้แล้ว ห้ามแก้กลับ**
- `ERP` ต้องใช้ขอบเขตคำ `\b(?:H)?ERP\b` ไม่งั้นไปโดน **CAT·ERP·ILLAR** (เครื่องกำเนิดไฟฟ้า)

- `…คลัง` ต้องต่อท้ายด้วย `(?!ข้อมูล|ข้อสอบ)` — `โปรแกรมคลังข้อมูลด้านการแพทย์` คือ data warehouse

## กลุ่มที่ 4 — โลจิสติกส์ใน รพ. (เพิ่ม 21 ก.ย. 2569)

ไฟล์ `egp-hospital-logistics-2569.md` → `logistics-market-report.html` · 3,019 โครงการ · 1,127 ล้านบาท

ครอบคลุมงานเคลื่อนย้ายคน-ของ-ผ้า-ขยะ-อาหาร ทั้งฝั่งจ้างเหมาบริการและฝั่งระบบ/เครื่อง/ซอฟต์แวร์

**ข้อค้นพบหลัก** — **2,207 จาก 3,019 โครงการ (73%) คิดเป็น 85% ของมูลค่า เป็นงานจ้างเหมาแรงงานล้วน**
ที่ไม่มีระบบหรือเครื่องจักรพ่วงเลย ส่วนที่มีระบบมีเพียง 812 โครงการ 174 ล. — ช่องว่างนี้คือ
ขนาดตลาดที่ยังแปลงเป็นระบบได้ รายงานมีตัวกรอง **"ลักษณะงาน"** ไว้สลับดูสองฝั่งโดยเฉพาะ

**เวรเปลมีสองฝั่ง ห้ามปนกัน** — การจ้างพนักงานเปลคือค่าแรง (อยู่หมวดจ้างเหมา) ส่วน
`ระบบจัดเวรเปล (Porter Dispatch)` คือซอฟต์แวร์ที่ขายให้ รพ. (อยู่หมวดซอฟต์แวร์)
ปีงบ 2569 มี 5 ราย 726,220 บาท ที่ สถาบันบำราศนราดูร · รพ.พระนั่งเกล้า ·
ราชวิทยาลัยจุฬาภรณ์ · รพร.สระแก้ว · รพ.ศีขรภูมิ — ขอบเขตจึงต้องรับคำนำหน้า
ทั้งฝั่งคน (`พนักงาน|เวร|งาน|บริการ`) และฝั่งระบบ (`ระบบ|โปรแกรม|ซอฟต์แวร์|จัดการ|บริหาร|ศูนย์`)
โดยคง `(?!ี่ยน|ือก|ว)` ไว้เสมอ ไม่งั้นไปโดน "บริการเปลี่ยนอะไหล่"

### กลุ่มนี้ใช้เกณฑ์คัดกรองคนละชุดกับอีกสามกลุ่ม

สามกลุ่มเดิมสำรวจ "ระบบ/โปรแกรม" จึงตัดงานจ้างเหมาคนทิ้งหมด แต่ครึ่งหนึ่งของตลาดโลจิสติกส์
คืองานจ้างเหมาบริการ ถ้าใช้เกณฑ์เดิมจะเหลือศูนย์ `lib/filter.js` จึงมี `GROUP_RULES` ให้ override
รายกลุ่ม โดย**ค่า default อ้างอิงตัวแปรเดิมทุกตัว** — สามกลุ่มเดิมจึงทำงานเหมือนเดิมเป๊ะ

| จุดที่ผ่อนให้กลุ่ม `log` | เหตุผล |
|---|---|
| ปิด `IS_SYSTEM` | "จ้างเหมาบริการรับ-ส่งเวชภัณฑ์" ไม่มีคำว่าระบบ/เครื่อง แต่เป็นดีลจริง |
| เอา `จ้างเหมาบุคลากร` · `จ้างเหมาพนักงาน` ออกจากคำตัด | "จ้างเหมาพนักงานเปล" คือแกนของตลาดนี้ |
| เอา `ลิฟต์` ออกจากคำตัด | ต้องเก็บ "ลิฟต์ขนของ" ซึ่งเป็นระบบลำเลียงในอาคาร |
| เอา `รถตู้` · `เหมารถ` ออกจากคำพ้อง | เคยตั้งไว้ดัก Kiosk ผิด แต่รอบนี้รถรับส่งคือของจริง |
| เพิ่ม gate `COMMODITY_LOG` | กันตัวสินค้าที่ถูกขน (น้ำยา · วัสดุบริโภค · อาหารสด) ไม่ให้ปนกับงานขน |

`SCOPE.log` จึงต้องเขียนเป็นคู่ **"กริยา + สิ่งของ"** ไม่ใช่รายการคำเดี่ยวแบบกลุ่มอื่น
เพราะศัพท์โดเมนนี้กำกวมแทบทุกคำเมื่ออยู่ลำพัง

**กับดักที่ดักไว้แล้ว ห้ามแก้กลับ** (วัดจากผลจริง 10,231 รายการรอบสำรวจแรก ก่อนรัดเกณฑ์)
- `เปล` ต้องมี `(?!ี่ยน|ือก|ว)` เสมอ ไม่งั้นไปโดน **"บริการเปลี่ยนอะไหล่"** · เปลือก · เปลว
- `ซัก` ไปโดน **ซักซ้อมแผน** / **ซักประวัติผู้ป่วย** ต้องต่อด้วย ฟอก/อบ/รีด/ผ้า
- `GPS` ไปโดน **"Protege GPS self-expanding stent"** ต้องผูกกับ รถ/ยานพาหนะ/Ambulance
- `สิ่งส่งตรวจ` ส่วนใหญ่คือ **น้ำยาตรวจวิเคราะห์** และ **OUT LAB** (ค่าตรวจ ไม่ใช่ค่าขนส่ง)
- `อาหาร` ไม่ระบุกริยา = **ซื้อวัตถุดิบ** (ซื้ออาหาร 7 หมวด 67 ล.) เก็บเฉพาะ ประกอบ/บริการ
- `เครื่อง` ใน **"เครื่องผ้าผู้ป่วย"** ไม่ใช่เครื่องจักร จึงต้องมี `HAS_SYSTEM_LOG` แยกจาก `IS_SYSTEM`

**คำที่เกิน `MAX_ROWS` (6,000) ห้ามใส่กลับ** — `ประกอบอาหาร` 129,520 · `จ้างเหมาประกอบอาหาร` 86,789 ·
`ยานพาหนะ` 80,073 · `พนักงานขับรถ` 6,985 · `กำจัดขยะ` 6,061
การค้นของ API **ไม่ใช่ phrase search** เติมคำนำหน้าไม่ได้ทำให้แคบลง ต้องแตกเป็นคำที่ผูกกับ รพ. แทน
(`อาหารผู้ป่วย` 1,420 · `พนักงานขับรถพยาบาล` 47) — **ห้ามขยับ cap** เพราะ API จะตัดกลางคัน
จนได้ตัวอย่างที่ไม่เป็นตัวแทน

**พื้นวงเงิน 20,000 บาท** (`minMoney` ใน `config.js` — `watch-daily.js` บังคับด้วย) — ก่อนใส่พื้นมี
6,434 โครงการ 1,162 ล. ส่วนที่ตัดคือสัญญาจ้างรายวัน/รายเดือนหลักร้อยถึงหลักพัน
(เช่น "จ้างเหมาทำงานหน่วยงานซักฟอก 335 บาท") = 3.1% ของมูลค่าแต่ 53% ของจำนวนแถว
